# Operating Model Canvas — Module

Use in Stage 2 (current state) and Stage 4 (target state). Fill one canvas per state
so the two can be compared dimension by dimension.

---

| Dimension | Guiding question | Current / Target description | Evidence / root cause link |
|-----------|------------------|------------------------------|----------------------------|
| **Value proposition & customers** | Who do we serve and what outcome do they pay for? | | |
| **Processes** | Which end-to-end processes deliver that outcome? Who owns each? | | |
| **Organisation & people** | Structure, spans, roles, capacity, critical skills | | |
| **Governance & decision rights** | Which decisions, taken by whom, in which forum, how fast? | | |
| **Performance management** | Which KPIs, reviewed how often, tied to which incentives? | | |
| **Information & enablers** | What information must flow between whom? (business need only — no system design) | | |
| **Culture & behaviours** | Which behaviours are rewarded in practice? | | |
| **Locations & sourcing** | Where is work done, in-house vs. partner? | | |

## Rules

- Stage 2: describe what *is*, with evidence. Technology appears only under
  "Information & enablers" as observed context.
- Stage 4: every target-state row must cite the root cause(s) it resolves (`RC-NNN`)
  and the option it implements (`OPT-NN`).
